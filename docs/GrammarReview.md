# 文法审查

建议定期由一个非 Claude 的 agent（例如 DeepSeek）审查 Claude 提交的改动的文法，再由 Claude 确认，最后以提交信息中的标记记录检查点（作者 2026-10-13 决定）。

## 动机

Claude 写作时反复出现拟人与口语化的写法，自查无法可靠地发现。换一个模型审查，可以覆盖 Claude 自身的盲区。

2026-10-13 的一次全仓库审查同时表明，审查方的修正也会出错：文档中约 9 处被改变了原意（例如把「UTAU 无法区分两种编码」改为「读取结果相同」，把已修正的错误写成当前的行为，把因果关系改反），改名与已有的函数重名，新增的 TODO 本身违反文体。因此下文限定审查的范围，并要求 Claude 以意思为主进行确认。

## 时机

审查是建议而非每次提交的前提。以下任一情况出现时建议审查一次：

- 距上一个检查点约 5 至 10 个提交。
- 针对一项功能的一组连续改动已经完成，且改动范围不大。

## 流程

1. Claude 照常提交改动，每个提交经作者同意。
2. 审查方审查上一个检查点之后的改动，修正后提交。
3. Claude 确认审查方的修正。
4. 确认完成后，在最后一个提交的信息末尾加上 ` [GRAMMAR CHECKED]`。检查点之后的提交在审查完成之前不推送。

## 审查范围

审查对象是上一个检查点之后新增或修改的行，即 `git diff <上一个带标记的提交>..HEAD` 的内容。上一个检查点以 `git log --grep "GRAMMAR CHECKED" -1` 查找。

审查的内容是注释、文档、`tr()` 界面文字与译文，以及函数、变量、类型的命名，依据是 `CLAUDE.md`「代码编写」中的「文体」一节与 [`Development.md`](Development.md)。

**不修改审查范围以外的文字。** 旧文字中的问题列出来交给作者，不在审查中顺带改写。范围扩大会使确认的成本成倍增加，而且改错原意的情况主要出现在这些顺带改写的旧文字中。

**审查方不修改规则本身。** 认为 `CLAUDE.md` 或 `Development.md` 需要修改时，作为建议交给作者。

## 审查方的修正

- **修正不得改变原意。** 只改写法，不增删条件、情况、因果与约束，不引入原文没有的事实。删去一句之前，确认后文没有依赖其中的术语或前提。
- **拿不准的地方只报告，不修改。** 包括无法确定原意，以及无法确定代码行为的情况。
- **删标点前先确认它的作用。** 逗号可能把状语与谓语分开，去掉后状语会被吸进从句。例如 `are checked, again whenever the source format changes` 表示先勾选一次、此后每次变化时再勾选，改成 `are checked again whenever …` 就丢掉了「先勾选一次」（2026-10-15 的审查中出现两处）。删去逗号、分号或冒号之前，把标点恢复后重读一遍。这一条不在「不增删条件」的字面之内：删一个逗号不增删任何词，意思却可能改变。
- **明显是插入位置错误的地方只报告，不连带改写。** 例如一条注释被新增的内容拆成两半，或一句话被插进另一句中间。判断某一行原本属于哪一段是改写，不是修正，留给作者或 Claude。2026-10-15 的审查中，审查方对被拆开的一条注释即是如此处理。
- **命名的修改须保证构建与受影响的测试通过。** 改名前确认新名称不与已有的成员重名，命名参照 Qt 中同类成员。审查方无法构建时，只提出命名建议，由 Claude 实施、构建并运行受影响的测试。
- **审查方的提交遵守 `CLAUDE.md`「提交」一节**：一行英文祈使句，不带署名，一个提交只做一件事，经作者同意后提交。
- **审查方不打检查点标记，也不确认自己的修正。** 审查与确认由不同的一方进行：审查方提交修正时不加 ` [GRAMMAR CHECKED]`，标记只由 Claude 在确认之后加上。2026-10-14 的一次审查中，审查方自行打了标记，确认这一步被跳过，事后 Claude 的确认发现其中 2 处修正改变了原意。

## Claude 的确认

确认的重点是意思，而非文法。Claude 逐条比较修正前后的文字，判断意思是否相同，必要时对照代码。意思被改变的地方改回原意，或改为既符合文体又不改变原意的写法。

文字量大时，可以先用脚本过滤掉只有大小写、换行与拼写差异的改动，只核对措辞有变化的部分。标点的改动不在过滤之列，须逐条核对，因为删去一个逗号就可能改变意思，见上文。

## 检查点标记

标记为提交信息末尾的 ` [GRAMMAR CHECKED]`，例如 `Restore the meaning of three header comments [GRAMMAR CHECKED]`。这是 `CLAUDE.md` 中「只写一行英文祈使句」的唯一例外。

- 确认中有修正时，Claude 的最后一个修正提交直接带上标记。
- 确认中没有修正时，以 `git commit --amend` 给当时的最后一个提交加上标记。审查完成之前不推送检查点之后的提交，因此改写这些提交是安全的。修改提交信息同样须经作者同意。

## 分歧

Claude 不同意审查方的某处修正，而该处不属于改变原意时，列出该处与双方的理由，交给作者裁决，不自行回退。
