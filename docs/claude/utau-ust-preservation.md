# UTAU 0.4.19 对 UST 未知内容的保留行为

`_USTH_` 控制音符的可行性依赖于 UTAU 在打开并保存文件时原样保留部分未知内容。本文档记录实测得到的边界。结论来自 UTAU 0.4.19 正式版在 Windows 上的「打开 → 名前を付けて保存」操作，探针文件和比较脚本位于 `.cache/utau-probe/`，可重复执行。

所有结论均为实测结果，而非推断。修改本文档前必须重新运行探针。

## 载体：可保留内容的位置

| 位置 | `$` 开头的未知条目 | 不带 `$` 的未知条目 |
|---|---|---|
| 音符段 `[#NNNN]` | **保留** | 丢弃 |
| `[#SETTING]` | 丢弃 | 丢弃 |
| `[#VERSION]` | 丢弃 | 丢弃 |

**音符段是唯一的载体**，且条目必须带 `$` 前缀。这解释了 UTAU 自身的 `$direct`、`$patch`、`$region`、`$region_end` 为何采用这种形式：它们只是这一通用命名空间中的几个实例。

`Label` 是例外：它不带 `$` 但会被保留，因为它是 UTAU 自身的条目。

条目顺序**不保留**。未知的 `$` 条目一律被移至段尾，即使原本位于 `Length` 之前，写回后也位于最后。因此不得依赖条目位置表达任何含义。

同名键重复时**后者生效**，只保留一条。

## 禁止自定义段落

未知段落不会被忽略，而是被**当作音符**处理。实测将 `[#HUPDATA]` 置于 `[#SETTING]` 与 `[#0000]` 之间，UTAU 保存后它变成一个 `Length=15`、`NoteNum=24`、歌词为空的音符，其中的 `$` 条目随之进入该音符，**其后所有音符的索引后移一位**，且没有任何提示。

由此得出两条推论：

- HelloUTAU 写出 UST 时绝不能创建自定义段落。
- HelloUTAU 读取 UST 时遇到无法识别的段名，**静默跳过**，见 [`note.md`](../note.md)。

## 载荷：值中允许的内容

长度没有实际上限，65536 个字符的值被原样保留，整个文件除 `CacheDir` 外逐字节相同。

| 行为 | 字符 |
|---|---|
| 原样保留 | `, ; % \ " # [ ] $ @ + / - _ . : \| ~ ^ & * ( ) < > ? ! ' \`` |
| 空格被替换为逗号 | `A B` → `A,B`，`A  B` → `A,,B`，前导与尾随空格同样处理 |
| 值被截断 | `=`，`A=B` → `A`，`A==B` → `A` |
| 值被截断，且本段其后的所有条目被丢弃 | 制表符 |
| 整条删除 | 空值 |

制表符的行为由两次实测共同确定。probe2 中制表符条目之后的四个条目全部消失；probe4 将这四个条目分别放在不同的音符上重新测试，四个条目均被保留。因此条目丢失是制表符导致的连带效应，而非这些条目自身的问题。

`=` 导致截断，这直接排除了**带填充的 base64**。

## 键名

未发现任何约束。大写字母、连字符、点、纯数字、单字符键 `$h`、64 个字符的长键名均被原样保留。单个音符带 40 个未知条目时也全部保留，未测出数量上限。

## 由此确定的载荷格式

- **字母表采用去除填充的 base64url**：`A-Za-z0-9-_`。这些字符均已实测通过，且本身不含空格、制表符和 `=`。
- **值不得为空。** 空值会导致整条被删除，因此配置内容为空时也必须写入占位符，否则读取时无法区分「条目不存在」与「条目为空」。
- 载荷本身必须是**纯 ASCII**，因为读取时要先按字节定位载荷，再决定整个文件的解码方式，见 `docs/note.md` 的编码策略。base64url 满足此要求。
- 往返测试的断言为：任意字节序列 → 编码 → 写出 UST → 读取 UST → 解码，结果与原序列相同。

## 附带确认的事项

UTAU 会将 `CacheDir` 改写为 `<保存的文件名>.cache`，使其随文件名变化。缓存目录位于工程文件旁边，这不是约定，而是 UTAU 的实际行为。

`Tool1`、`Tool2`、`VoiceDir` 被原样保留，即一份 UST 能将引擎路径传递给下一个打开它的用户。CVE-2024-28886 是否利用了这一途径，官方未作说明，不得将这一现象当作该漏洞的解释。

## stdutau 的相应支持

音符段内的未知条目存入 `utau::Note::userData`，写回时置于段尾，与 UTAU 的位置一致；`PBType` 和 `@preuttr` 系列条目有专门的守卫，防止被当作未知条目重复写出。相关测试位于 `tests/auto/test_ustfile.cpp`。

该库比 UTAU 更宽松：不带 `$` 的条目和空值都会保留。**宽松的是库，而非 UTAU**，因此决定存储内容时仍以本文档的表格为准。
