# UTAU 0.4.19 对 UST 未知内容的保留行为

`_USTH_` 控制音符能成立，靠的是 UTAU 打开再保存时会原样留下某些它不认识的东西。这份文档记录实测出来的边界。结论来自 UTAU 0.4.19 正式版在 Windows 上的「打开 → 名前を付けて保存」，探针文件和比对脚本在 `.cache/utau-probe/`，可重放。

所有结论都是实测的，不是推断的。要改这份文档，先重跑探针。

## 载体：什么地方留得住

| 位置 | `$` 开头的未知条目 | 不带 `$` 的未知条目 |
|---|---|---|
| 音符段 `[#NNNN]` | **保留** | 丢弃 |
| `[#SETTING]` | 丢弃 | 丢弃 |
| `[#VERSION]` | 丢弃 | 丢弃 |

**音符段是唯一的载体**，且必须带 `$` 前缀。这解释了 UTAU 自己的 `$direct`、`$patch`、`$region`、`$region_end` 为什么都长这样，它们只是这个通用命名空间里的几个实例。

`Label` 是个例外，它不带 `$` 但会被保留，因为那是 UTAU 自己的条目。

条目顺序**不保留**。未知 `$` 条目一律被移动到段尾，放在 `Length` 之前的写回去也在最后。所以不要依赖条目位置表达任何含义。

同名键重复时**后者胜**，只留一条。

## 不要造自定义段落

未知段落不是被忽略，是被**当成音符**。实测把 `[#HUPDATA]` 放在 `[#SETTING]` 和 `[#0000]` 之间，UTAU 存回来时它变成了一个 `Length=15`、`NoteNum=24`、歌词为空的音符，它携带的 `$` 条目跟着进了这个音符，**后面所有音符索引顺移一位**。没有任何提示。

两条推论：

- HelloUTAU 写 UST 时绝不能造自定义段落。
- HelloUTAU 读 UST 时遇到不认识的段名，要当成**文件已损坏**处理，不能跳过。跳过会和 UTAU 的解释产生分歧，而用户手里的那份已经被 UTAU 改成音符了。

## 载荷：值里能放什么

长度没有实际上限，65536 字符的值原样保留，整个文件除 `CacheDir` 外逐字节相同。

| 行为 | 字符 |
|---|---|
| 原样通过 | `, ; % \ " # [ ] $ @ + / - _ . : \| ~ ^ & * ( ) < > ? ! ' \`` |
| 空格被替换成逗号 | `A B` → `A,B`，`A  B` → `A,,B`，前导和尾随同样 |
| 截断值 | `=`，`A=B` → `A`，`A==B` → `A` |
| 截断值，并丢弃本段其后的所有条目 | 制表符 |
| 整条被删 | 空值 |

制表符那条是两次实测合起来才看清的。probe2 里制表符条目后面还有四条，全部消失；probe4 把它们隔离到各自的音符上重测，四条都活了。所以是制表符的连坐，不是它们各自的问题。

`=` 会截断这一点直接否掉**带填充的 base64**。

## 键名

没有发现约束。大写、连字符、点、纯数字、单字符 `$h`、64 字符长名都原样保留。单个音符挂 40 条未知条目也全部保留，没测出数量上限。

## 由此确定的载荷格式

- **字母表用 base64url 去填充**：`A-Za-z0-9-_`。这套字符全部实测通过，且天然不含空格、制表符和 `=`。
- **值不许为空**。空值整条会被删掉，所以配置内容为空时也要写一个占位符，否则读回来分不清「没有这条」和「这条是空的」。
- 载荷本身必须是**纯 ASCII**，因为要先按字节定位再决定怎么解码整个文件，见 `docs/note.md` 的编码策略。base64url 满足这一条。
- 往返测试的断言是：任意字节序列 → 编码 → 写 UST → 读 UST → 解码 == 原串。

## 顺带确认的两件事

`CacheDir` 会被 UTAU 改写成 `<保存的文件名>.cache`，跟着文件走。缓存目录开在工程旁边不是约定，是 UTAU 的实际行为。

`Tool1`、`Tool2`、`VoiceDir` 原样保留，也就是说一份 UST 能把引擎路径带给下一个打开它的人。CVE-2024-28886 走的是不是这条路，官方没说，别把这条当成那个洞的解释。

## stdutau 这一侧

原先 `Note::userData` 声明了但全仓库零引用，`$direct`、`$patch`、`Label` 三个常量定义了但解析和写出都没碰，也就是说载体在库这一层就先漏了。

现在补上了：音符段内未知条目落进 `utau::Note::userData`，写回时放在段尾，与 UTAU 的位置一致；`PBType` 和 `@preuttr` 一族有守卫挡着，免得被当成未知条目写第二遍。覆盖在 `tests/auto/test_ustfile.cpp`。

库这一侧比 UTAU 宽松：不带 `$` 的条目、空值它都留着。**宽松的是库，不是 UTAU**，所以决定往里存什么的时候仍以本文档的表格为准。
