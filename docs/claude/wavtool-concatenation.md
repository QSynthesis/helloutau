# 实测：wavtool.exe 的拼接规则

实测于 2026-09-28，对象是 UTAU 自带的 `wavtool.exe`（65536 字节，文件日期 2010-02-19），为 [`../Synth.md`](../Synth.md)「三、实时」的进程内拼接（`WavtoolMixer`）提供依据。

## 方法

工具在 `.cache/claude/tools/wavprobe/`（不纳入版本库），只使用临时目录中的合成文件与设置中的 wavtool：

- `probe.py`：写出合成的 44100 Hz 16 位单声道输入，以不同参数调用 `wavtool.exe`，读取它写出的 `.dat`，按分段线性输出。输入有恒定 ±10000、20000 的直流，以及第 i 个样本值为 i 的斜坡（可以直接读出取自输入的哪一个样本）。六轮分别测基本规则、细节、非整数的取整、负数重叠与 stp、包络点的位置、异号样本的相加。
- `replay.py` / `growth.py`：以真实工程的 106 次调用逐次回放（输入换成直流），对照每次调用后轨道的长度。
- `crossfade.py`：以直流复现真实工程中一对交叉淡化的音符，逐样本对照。
- `ustrender --compare-mix`（`hellokit/tests/manual/ustrender`）：以 wavtool 完整渲染一个真实工程，再以同一组片段在进程内拼接，逐样本比较。

命令行形式为

```
wavtool <out> <in> <stp> <length>@<tempo>±<correction> p1 p2 p3 v1 v2 v3 v4 ovr p4 p5 v5
```

## 结果

以下 ms 为毫秒，「换算」指乘以 44.1 得到样本数，「取整」指四舍五入（.5 远离零：65 ms 为 2866.5，取 2867）。

### 截取与长度

**一切位置都在输入的时间轴上换算。** 设 stp 换算取整后为 S（跳过输入开头的样本数），则输入中毫秒位置 t 对应本段的第 `取整((stp + t) × 44.1) − S` 个样本。

- **stp 跳过输入开头**：stp 为 10 时输出的第一个样本是输入的第 441 个，10.01 时仍是 441，10.02 时是 442。
- **本次追加的长度**：设 `length` tick 在 `tempo` 下的毫秒数加 `correction` 为 L 毫秒，则写出 `取整((stp + L) × 44.1) − S` 个样本。stp 为 0 时即 `取整(L × 44.1)`：`480@120+0.01` 为 22050 个样本，`480@120+0.02` 为 22051 个。stp 不为 0 时可能少一个：`720@134+89.5522`（33568.66 个样本）在 stp 为 30.4478 时写出 33568 个，在 stp 为 30 时写出 33569 个。曲速只用于换算：`240@60` 与 `480@120` 相同。
- 输入比所需长度短时，其后补零；输入文件不存在时（UTAU 为休止符传入 `R.wav`）整段为静音，此时命令行只有 `<stp> <length> 0 0`。

### 包络

包络点的位置以本段为基准，按上面的规则换算：

| 点 | 毫秒位置 t | 音量 |
|---|---|---|
| 起点（隐含） | 0 | 0 |
| 1 | p1 | v1 |
| 2 | p1 + p2 | v2 |
| 5（给出 p5 与 v5 时） | p1 + p2 + p5 | v5 |
| 3 | L − p4 − p3 | v3 |
| 4 | L − p4 | v4 |
| 终点（隐含） | 本段末尾（写出的样本数） | 0 |

- **每个点由毫秒位置直接换算，不是逐段累加**：p1、p2 都为 10.01 时，点 1 在第 441 个样本，点 2 在 `取整(20.02 × 44.1)` = 第 883 个，而不是 441 + 441。
- **点 3、点 4 从精确长度 L 往回算，不是从取整后的样本数**：长度 491.7612 ms、p3 为 75 时，点 3 在 `取整(416.7612 × 44.1)` = 第 18379 个样本；从取整后的 21687 个样本减去 3307.5 则会得到 18380。前后两个音符的交叉淡化只有这样才能对齐（相加后恒为同一值）。
- 未给出 p4 时按 0 计，点 4 即在末尾。只给出 p4 而无 p5、v5 时，没有点 5。
- 音量为百分比，可以超过 100（v 为 150、200 时输出 15000、20000）。
- 相邻两点之间**线性插值**。**几个点落在同一个样本上时，那里取最后一个点的音量**：`0 0 0 100 100 100 100` 的起点、点 1、点 2 都在第 0 个样本，第 0 个样本的增益即为 100%。

### 相加与截断

- 下一次追加从**当前末尾向前 ovr 毫秒处**开始（换算取整；10.01 毫秒为 441 个样本，10.02 毫秒为 442 个），重叠区中新旧样本**相加**，不交叉淡化：10000 与 20000 重叠 100 毫秒，重叠区为 30000。第一次追加的 ovr 不起作用。
- **每个样本 = 向零截断（原有的整数样本 + 输入样本 × 增益），再截到 16 位的范围**。截断作用于和，而非单独作用于新样本：原有样本为 -4000、新贡献为 10000 × 1/441 ≈ 22.68 时，`wavtool.exe` 输出 -3977（先截断新样本再相加则为 -3978）。单独一段时即「输入 × 增益向零截断」：增益 0.5 × 1/882 时 10000 得 5，-10000 得 -5。20000 与 20000 相加得 32767。截断发生在每一次追加时，因此三段以上重叠时，结果取决于追加的顺序。
- **负数的 ovr 在前一段之后留出空隙**，空隙为 `max(0, 取整(−ovr × 44.1) − 1)` 个样本，比 |ovr| 换算的样本数少一个：-30 ms 为 1322 个，-10.99 ms 为 484 个，-0.035 ms 为 1 个，-0.01 与 -0.02 ms 为 0 个。

### 输出文件

第一次调用写出 44 字节的 `.whd` 与 `.dat`，此后每次调用改写 `.whd` 中的两个长度并向 `.dat` 追加。`.whd` 为标准的 PCM 文件头：单声道、44100 Hz、16 位。

### 异常输入

- **重叠超过已有的输出**（前一段 250 毫秒，重叠 400 毫秒）：输出开头出现 -22768、32767 等无规律的值，是读到了数据之前的内容。这不是可以复现的规则，`utau::Synth::calc` 也不产生这样的参数。
- **包络点交叉**（p1 + p2 超过 L − p4 − p3）：`wavtool.exe` 以 -1 退出，不写出任何内容。只测了作为第一次调用的情形，未测它出现在一系列调用中间时的影响。

## 真实工程上的比较

`ustrender --compare-mix` 以 `cuowei.ust`（106 个音符，曲速 134，含负数重叠与非零 stp，GBK 中文音源，UTAU 自带的 `resampler.exe` 与 `wavtool.exe`）渲染并比较：两者都是 1767277 个样本，**82 个样本相差 1，其余完全相同**，在 `Synth.md` 规定的允许差异之内。

规则是逐步修正的，每一步都由这一比较暴露：最初以毫秒换算后逐段累加、先截断再相加，138 万个样本不同且长度差 14 个样本；改为本文的规则后降至上述结果。

## 进程内拼接的规定

`WavtoolMixer` 按上述规则逐次模拟追加。两种异常输入不复现：重叠超过已有输出时本段从 0 开始，包络点交叉时按点的顺序插值。
