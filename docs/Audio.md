# 音频输出与混音改造方案

## 实现状态（2026-10-09）

本方案已实现，进程内只有一个 `QAudioSink`。与下文方案的出入如下：

- `AudioEngine` 是全局单例（`AudioEngine::instance()`），不由 `Editor` 创建。各用途通过句柄 `AudioOutput` 注册声源，混音器为 `AudioMixer`，声源编号在进程内唯一。
- 每个声源注册时必须给出自己的采样率，与已打开的流不同时拒绝，见 `AudioOutput::start()`。
- 设备切换或设备丢失时关闭流，正在播放的声源停止，各窗口报告原因，由用户重新开始播放。不保存、不恢复声源的位置。
- 设置页只有输出设备下拉框、「Test」按钮与说明文字，没有设备状态与刷新按钮。下拉框的设备列表在打开设置页时取得。
- 测试声音在下拉框所选的设备上播放，见「设置页」一节末尾。
- 「Windows 手工测试」各项尚待作者验收，见 [`Status.md`](Status.md)「待定事项」。

## 问题

当前 `AudioOutput` 的每个实例都创建一个 `QAudioSink`。钢琴键预览、工程播放和音源试听分别持有自己的输出对象。两个对象在同一输出设备上同时播放时，Windows 音频后端可能出现左右声道状态异常。停止其中一个输出只能规避部分触发顺序，不能解决反向触发的情况。

钢琴键预览未结束时开始工程播放，以及工程播放过程中点击钢琴键，都会使两个输出流重叠。拔出并重新插入耳机可以重置设备状态，因此现象会暂时消失。

## 目标

1. 进程内只创建一个播放用的 `QAudioSink`。
2. 钢琴键、工程播放和音源试听都通过同一个混音器输出。
3. 新增和移除声源不会重建输出设备，也不会让其他声源中断。
4. 输出设备可以在设置页选择，并提供测试声音。
5. 输出设备断开、切换和重新连接时，错误能够传回界面，不能静默播放无声数据。

## 结构

### `AudioEngine`

在 Audio 模块中增加一个应用级音频引擎。它负责输出设备、混音器和声源生命周期。引擎在应用中只有一个实例，由 `Editor` 创建并持有。

建议接口如下：

```cpp
class AudioEngine : public QObject {
public:
    bool startSource(std::shared_ptr<AudioSource> source, SourceId *id = nullptr,
                     QString *error = nullptr);
    void stopSource(SourceId id);
    void stopAll();

    QList<QAudioDevice> outputDevices() const;
    QAudioDevice outputDevice() const;
    bool setOutputDevice(const QAudioDevice &device, QString *error = nullptr);
};
```

`AudioOutput` 可以保留为声源接口的兼容外壳，但不能再由每个调用方直接创建 `QAudioSink`。迁移完成后，应用代码只依赖 `AudioEngine` 或一个面向用途的播放句柄。

### `Mixer`

混音器运行在 `QAudioSink` 的音频回调线程中。每次回调执行以下步骤：

1. 将输出缓冲区清零。
2. 读取当前声源列表的快照。
3. 逐个声源读取相同数量的帧。
4. 将声源的每个通道累加到输出缓冲区。
5. 对混音结果执行增益限制，避免多个声源叠加后削波。
6. 记录已经结束的声源，并在非音频线程中发出完成通知。

声源的 `read()` 仍然只能执行无阻塞、无分配操作。声源列表不能在回调线程中加锁。控制线程使用原子交换的不可变快照，或使用已经验证过的无锁队列提交增加和移除操作。

### 声源通道规则

- 单声道声源复制到设备的所有输出通道。
- 多声道声源按通道序号混合。
- 声源通道数少于设备通道数时，缺少的通道补零。
- 声源通道数多于设备通道数时，超出的通道被丢弃。
- 所有声源在进入混音器前转换到设备采样率。

钢琴键的 `PianoToneSource` 与设置页测试声音的 `SineWaveSource` 都是单声道，因此在各声道上相同。

## 生命周期

### 引擎启动

应用启动时创建 `AudioEngine`，读取 App Settings 中保存的输出设备标识。若保存的设备不存在，使用系统默认设备并在设置页标记原设备不可用。

### 开始播放

播放请求只向引擎注册一个声源，并获得一个 `SourceId`。工程播放、钢琴键和音源试听可以同时存在，混音器负责把它们合并到同一个设备流。

### 停止播放

停止请求只移除对应的 `SourceId`。除非用户切换设备或设备报告错误，否则不调用 `QAudioSink::stop()`，也不销毁输出设备。

### 设备切换

设备切换在主线程执行：

1. 暂停向旧设备提交新的回调数据。
2. 保存当前活动声源及其位置。
3. 停止并销毁旧的 `QAudioSink`。
4. 创建新格式的 `QAudioSink`。
5. 恢复声源列表，不能重复播放已经消费的帧。

设备切换是唯一允许重建输出流的常规操作。

## 设置页

在“音频”设置页显示：

- 输出设备下拉框。
- 当前设备的采样率、通道数和状态。
- 测试按钮。
- 设备不可用时的错误文本。
- 刷新设备列表按钮，处理耳机插拔后的设备变化。

测试按钮向同一个 `AudioEngine` 注册短促的正弦波声源。测试结束后只移除测试声源，不停止其他播放。

测试声音在下拉框所选的设备上播放，无须先应用（作者 2026-10-09 决定）。所选设备与已打开的流是同一设备时，测试声源并入该流的混音器。不是同一设备时，只在没有任何声源播放时关闭旧流、在所选设备上重新打开，否则拒绝并给出原因。因此进程内任何时刻都只有一个 `QAudioSink`。之后在已应用的设备上播放时，同样在没有声源播放时换回该设备。混音器的声源编号在进程内唯一，旧流中的编号不会指向新流中的声源。

设备标识保存到 App Settings。设备名称只用于界面显示，不能作为持久化键，因为同名设备可能同时存在。

## 迁移步骤

### 第一步：抽离设备格式

把选择设备、验证浮点格式、采样率转换和设备错误处理从 `AudioOutput` 中抽到 `AudioEngine`。补充没有可用输出设备和格式不支持的测试。

### 第二步：实现混音器

新增 `Mixer` 和声源句柄。先支持单声道 `BufferSource` 与 `SineWaveSource`，验证左右声道输出一致，再接入 `StreamSource` 和工程渲染结果。

### 第三步：迁移调用方

按以下顺序迁移：

1. 钢琴键预览。
2. `SamplePreview` 音源试听。
3. `Playback` 工程播放。
4. 设置页测试声音。

迁移期间禁止这些调用方直接构造新的 `QAudioSink`。

### 第四步：移除临时规避

删除播放开始时强制停止钢琴键预览的临时逻辑。播放和预览应当可以同时存在，并由混音器统一输出。

## 测试

### 单元测试

- 单声道声源在双声道设备上左右样本相同。
- 两个声源同时播放时，输出等于逐帧相加后的结果。
- 声源结束后不会继续读取无效数据。
- 移除一个声源不会影响其他声源的位置。
- 声源列表更新不会在音频回调线程分配内存或等待互斥锁。
- 输出缓冲区长度不是声道数整数倍时不会越界。

### Windows 手工测试

1. 点击钢琴键后立即开始工程播放。
2. 工程播放过程中点击钢琴键。
3. 工程播放、钢琴键和音源试听同时进行。
4. 播放过程中拔出并重新插入耳机。
5. 在设置页切换扬声器和耳机，并分别执行测试声音。
6. 连续快速点击多个钢琴键，确认左右声道始终同时有声。

验收条件是所有场景都只使用一个 `QAudioSink`，左右声道不会因为播放顺序或声源结束顺序而改变，且设备切换后可以继续播放。

## 暂不处理

- 不在本次改造中加入音量、声像和均衡器界面。
- 不改变渲染器输出文件的采样率和声道格式。
- 不允许每个窗口自行创建独立的音频设备流。
