# 合成

本文规定 `HelloKitSynth` 的结构。开始工作前应先阅读 [`note.md`](note.md)（产品形态）和 [`Roadmap.md`](Roadmap.md)（阶段与验收标准），安全底线见 [`../AGENTS.md`](../AGENTS.md)。

## 现有组件

| 组件 | 职责 |
|---|---|
| `EngineProcess` | 启动一次引擎。参数以向量传递，**不提供接受完整命令行的重载** |
| `SynthPlan` | 只计算不执行。将 `VoiceBank::find` 与 `utau::Synth::calc` 衔接，为每个音符生成两条已解析的参数向量 |
| `SynthRunner` | 执行一份 `SynthPlan` |

将计算与执行分离的理由：真正值得测试的部分，即歌词解析到哪个样本、相邻音符之间的时值校正、每个引擎实际接收的参数，因此无需磁盘上存在引擎即可测试。

## 三种策略的必要性

引擎的启动方式不是实现细节，而是**用户可见的兼容性选项**。

| 策略 | 必要性 |
|---|---|
| 经典 | **兼容性保底。** 部分重采样器依赖 `temp.bat` 的存在，甚至读取其内容 |
| 多线程阻塞 | 日常使用的策略。重采样调用相互独立，且占据几乎全部渲染时间 |
| 实时 | 编辑时即时试听。在界面实现之前只能建立模型 |

三种策略产出的音频应当一致，差异仅在于**调度方式**和**运行环境**。因此它们共用 `SynthPlan`，只在「取得计划之后如何执行」上分开。

## 共同的抽象

`SynthRunner` 是基类，三种策略是它的实现：

```
SynthRunner                 纯虚，render(plan, engines, observer, diagnostics)
├── ClassicSynthRunner       写出 temp.bat / temp_helper.bat，显示控制台窗口
├── ThreadedSynthRunner     N 个重采样并发执行，合成串行执行
└── RealtimeSynthRunner     按播放位置调度，可中断，可作废
```

**`SynthObserver` 报告进度并查询是否取消。** 它是接口而非回调函数，因为实时策略需要查询的不止「是否已取消」。它由工作线程调用，线程安全由实现方负责。这一点与 `InterchangeSelector` 理由相同：`hellokit` 不链接 QtWidgets，界面侧的事务不属于本层。

**引擎路径始终由宿主提供，不从工程中读取。** `Tool1`、`Tool2` 按原样保存，但不直接执行。这一规则对三种策略均成立，见 `AGENTS.md`。

## 一、经典（渲染脚本）

### 概述

官方 UTAU 在 `%TEMP%\utauX\` 下写出批处理文件并执行。单核时为 `temp.bat` 加 `temp_helper.bat`，多核时为 `temp.bat` 加 `temp1.bat`…`tempN.bat`：**重采样并行执行完毕后，才执行 `temp.bat` 进行合成**，与第二种策略结构相同。

**该策略是跨平台的。** 在 Windows 上写出 `temp.bat` 交给命令处理器执行，在其他系统上写出 `temp.sh` 交给 `/bin/sh` 执行（引擎在那些系统上运行于 Wine 中）。布局完全相同，只有语法不同：以 `cat` 代替 `copy /B`，以 `${var}` 代替 `%var%`，以单引号代替 `set "name=value"`。QSynthesis 当时采用的也是这种做法。

脚本类型由**运行时**选项 `ScriptShell` 决定，而非 `#ifdef`，因此两种脚本在任一平台上都能生成并测试，为另一平台生成的内容不必等到在该平台上运行时才首次检验。

大致内容如下（出自作者的[渲染脚本笔记](https://sinestriker.github.io/documents/QPitchEditor/book/Developers/UTAU-Tools/Rendering-Script.html)，**属于经验总结，而非官方规格**）：

- **页首**：一系列 `@set`，将曲速、采样率、音源目录、两个引擎、输出路径、helper 路径、缓存目录、全局 flags、默认包络存为变量；随后执行 `@del "%output%"`、`@mkdir "%cachedir%"`
- **正文**：休止符直接执行 `@"%tool%" "%output%" "%oto%\R.wav" 0 <长度> 0 0`；其余音符先执行 `@set params/flag/env/stp/vel/temp`，以 `@echo` 输出一行进度，再执行 `@call %helper% <九个参数>`
- **helper**：`@if exist %temp% goto A` 跳过重采样（即缓存复用）→ 执行 resampler → `:A` → 执行 wavtool
- **页脚**：确认 `%output%.whd` 和 `%output%.dat` 均存在，以 `copy /Y ... /B + ... /B` 合成 wav，再删除两个分片文件

`wavtool` 不直接写出 wav 文件，这一点已经实测确认：它向 `.whd`（44 字节文件头）和 `.dat`（PCM 数据）追加内容，最后将二者拼接。`SynthRunner` 采用相同做法。

### 保留的理由

[Wavtool 页面](https://sinestriker.github.io/documents/QPitchEditor/book/Developers/UTAU-Tools/Wavtool.html)提到，**moresampler 会读取 `temp.bat` 的内容**，以判断当前调用是否为最后一次。因此对于某些引擎，批处理文件的**文本本身**就是输入，而不只是启动方式。不写出批处理文件，这类引擎就无法工作。

控制台窗口也必须保留。官方 UTAU 使用可见的控制台，用户能直接看到脚本的输出；`stdc::Popen` 的 `startupInfo()` 支持 `STARTF_USESHOWWINDOW`，正是为此修改的。

### 两种引用模式与安全默认值

**这是全仓库唯一一处将工程中的字符串写入 shell 脚本的位置。** 官方 UTAU 直接拼接字符串，歌词或 flags 中只要包含 `&` 或换行符即可追加命令，这正是 CVE-2024-28886 的机制。

| 模式 | 行为 | 默认 |
|---|---|---|
| `Escaped` | 结构、命令、顺序、文件名、工作目录、控制台窗口均与官方一致，但赋值一律写为 `@set "name=value"`，值中的每个 `%` 加倍 | **是** |
| `Verbatim` | 完全复刻官方写法，不转义，按官方形式写为 `@set name=value` | 否 |

选择 `set "name=value"` 而非逐字符的 `^` 转义，是因为 cmd 在引号内不再解析运算符，`&`、`|`、`>`、`(` 均成为字面量，比逐字符转义更不易出错。`%` 仍须加倍，因为变量展开发生在引号解析之前。`!` 无需处理，因为延迟展开默认关闭，而音高字符串 `!120` 恰好包含该字符。

**引号和换行符无法写入。** `"` 会提前结束 `set "name=value"`，换行符会结束整行，这两者在该形式中都没有可用的转义方式。遇到时**报错并拒绝**，不写出残缺的脚本，因为写出错误的脚本比报告无法写出更严重。

命令行上的每个参数只在必要时（含空格或运算符时）加引号，而非一律加引号：UTAU 自身也是给路径加引号、数字不加引号，而部分引擎自行解析命令行而不经过 C 运行时，给数字加引号不能保证其仍被解析为数字。

原样复刻模式**必须由用户在明确的提示中选择**，提示须说明这意味着由工程文件决定执行哪些命令。不提供「记住我的选择」一类的全局开关。

提供两种模式而非只提供安全模式，是因为 moresampler 这类引擎会解析脚本文本，转义改变了文本，可能导致这类引擎出错。**这一点尚未实测。** 若遇到此类情况，即可获得证据；在此之前一律使用安全模式。

## 二、多线程阻塞

重采样调用相互独立，且占据几乎全部渲染时间；wavtool 向同一个文件追加内容，必须串行执行。因此流程如下：

```
N 个线程执行重采样  →  全部完成  →  按轨道顺序执行 wavtool  →  拼接 whd 与 dat
```

线程数可配置（`threadCount`），默认为硬件并发数，使用 QtCore 的 `QThreadPool`，不引入 QtConcurrent 模块。「阻塞」指调用方等待执行结束；界面侧须在工作线程上调用，这不属于本类的职责。

诊断按**轨道顺序**合并，而非按线程完成顺序合并，因为后者对用户不可读。取消意味着「不再启动新的音符，已在执行的调用允许完成」：中途终止引擎会在缓存中留下不完整的文件，下次渲染会将其当作有效结果。

缓存复用在此策略中实现：重采样前检查缓存文件是否存在。

### 引擎接缝

`SynthRunner::makeEngineProcess()` 是 protected 虚函数，默认创建真实的 `EngineProcess`。**引擎是第三方程序，不在本仓库中**，因此「参数交付之后」的行为原本无法被任何测试覆盖：wavtool 的两个分片如何拼接、上一次渲染的残留如何清除、分片未出现是否算作失败、`stopOnFirstFailure` 是否确实停止。覆盖这些行为的唯一方法是替换引擎。

`EngineProcess` 的析构函数和两个调用函数因此是虚函数。测试中的 `StandIn` 继承它，按测试的指定行为执行并记录收到的调用；四项行为各自经过突变验证（移除对应的实现后，对应的测试失败）。

**替身无法验证参数是否正确**，这由真实引擎验证，在 `tests/manual/utaucompare` 中与 UTAU 的渲染结果比较。

一个运行器在整个过程中只创建一个实例，由所有线程共用，因此替身必须支持多个线程并发调用。真实实现满足这一要求，因为它在两次调用之间不保留任何状态。

实时渲染需要接管这些调用，因此也通过这一接缝接入。

## 三、实时

在界面实现之前只建立模型。所需功能：

- **按播放位置排队**，优先渲染即将播放的音符
- **可作废**：修改一个音符后，该音符及受影响的相邻音符（先行发声与重叠会牵连前后音符）的缓存必须失效
- **可中断**：播放位置跳转后，正在执行的任务应视情况丢弃

结构参考 QSynthesis 的 `Frontend/Process/`（`RealtimeRenderer` + `ResampleWork` + `ConcatenateWork`）。**沿用其设计思路，不沿用其代码**，理由见 `Roadmap.md`。

以下是界面第 6 步（[`Widgets.md`](Widgets.md)）的设计，**作者已确认**。

### 范围

**实时试听只替换拼接，不替换重采样。** 重采样仍由设置中的 resampler 进程执行，参数与缓存片段与多线程策略完全相同（同一份 `SynthPlan`）；拼接不再调用 wavtool 进程，而在进程内按 wavtool 的规则把片段放到时间轴上。理由：

- wavtool 向一个文件追加内容，只能从头串行执行，无法从任意位置开始，也无法只替换其中一个音符。
- 重采样占据几乎全部渲染时间，而它本来就按音符独立，天然适合按播放位置调度。

完整渲染（第 5 步的「渲染后播放」，以及将来的导出）仍调用 wavtool 进程，是结果的标准。

### 组成

全部位于 `HelloKitSynth`，不链接界面；界面只提供播放位置、接收样本。

| 部分 | 职责 |
|---|---|
| 片段表 | 由当前的 `SynthPlan` 得到：每个音符的缓存片段、在轨道中的位置、包络、起始偏移与重叠。工程每次改动后重新计算 `SynthPlan`，与上一份逐步比较 |
| 调度器 | 维护待重采样的片段队列，按「距播放位置的先后」排序：播放位置之后的音符由近及远优先，其后是播放位置之前的音符。N 个线程执行，线程数同多线程策略 |
| 拼接器 | 在生产线程上把播放位置之后的一段时间（预读窗口，暂定 500 毫秒）按 wavtool 的规则混合为 44100 Hz 的样本，经 r8brain 的流式接口转换为设备采样率，写入无锁环形缓冲 |
| 音源 | `HelloUtauAudio` 的 `AudioSource` 的一个实现，音频线程只从环形缓冲读取，不加锁、不分配；`AudioOutput` 不变 |

**失效不需要单独的依赖分析。** 片段的文件名是全部重采样参数与样本状态的摘要（`cacheFileFor()`），音符或受牵连的相邻音符一旦改变，其片段名随之改变，旧片段自然不再被引用。拼接另外依赖 wavtool 的参数（包络、偏移、长度、重叠），因此两份计划逐步比较「片段名 + wavtool 参数」，不同的步骤即为失效，只重新混合这些音符覆盖的时间段。

**修改在预读窗口之后生效。** 环形缓冲中已混合的样本不回收，因此修改最迟在预读窗口的长度之后听到。播放位置跳转时清空环形缓冲并按新位置重排队列。

**正在执行的重采样不终止。** 与多线程策略相同：中途终止会在缓存中留下不完整的文件。跳转或修改使某个片段不再需要时，它照常完成并留在缓存中，下次可能复用。

### 与 wavtool 的一致性

进程内拼接须与 UTAU 自带的 `wavtool.exe` 一致。它的规则没有公开文档可引，因此先实测，结果写入 `docs/claude/`：

- 以合成的输入（恒定幅度的片段、可辨认的阶梯波形）调用 `wavtool.exe`，改变偏移、长度与校正、五个包络点与音量、重叠，读取 `.dat`，确定每个参数的含义：包络点的基准（片段起点还是终点）、音量的插值方式、重叠区是相加还是交叉淡化、长度如何截取片段。
- 实测只使用设置中的 wavtool 与临时目录中的合成文件。

**允许的差异**：对同一组片段，进程内拼接的结果量化为 16 位后，与 `wavtool.exe` 的输出逐样本相差不超过 1（一个最低有效位，源于浮点与定点的舍入）。以 `ustrender --compare-mix` 在真实工程上比较，并加入自动测试（以记录下来的 wavtool 输出为基准，不在测试中运行 wavtool）。

**实测结果**见 [`claude/wavtool-concatenation.md`](claude/wavtool-concatenation.md)，拼接由 `WavtoolMixer` 实现。在一个 106 个音符的真实工程上，两者长度相同，82 个样本相差 1，其余完全相同，符合上述规定。

### 实现

调度器与拼接器为 `RealtimeSynth`（`RealtimeSynth.h`）：按缓存文件跟踪每个片段的状态（待渲染、渲染中、就绪、失败），工作线程每次取距播放位置最近的待渲染音符；缓存目录中已有的片段直接读入；新计划保留仍被引用的片段；混合前检查所需片段是否就绪，生产线程可以等待就绪。失败的音符按静音处理并给出警告，不使播放一直等待。

以 `ustrender --realtime` 在上述真实工程上从空的缓存目录渲染（UTAU 自带的 `resampler.exe`，每个硬件线程一个工作线程）：开头一秒在 239 毫秒后就绪，全部 106 个音符在 1.6 秒后就绪；拼接出的整轨与 wavtool 的输出同样只有 82 个样本相差 1。

**用户选择了其他 wavtool 时**（如 wavtool4vcv、moresampler），实时试听仍按 `wavtool.exe` 的规则拼接，与完整渲染可能不同。界面在设置中说明这一点；完整渲染始终使用用户选择的 wavtool。

### 已确定的事项

- **播放到尚未重采样的音符时暂停等待**，界面显示「缓冲中」，片段就绪后继续。听到的始终是完整的结果。
- **空格键保持第 5 步的行为**（渲染后播放），实时试听另设命令。
- 预读窗口暂定 500 毫秒：越短修改生效越快，越长越不易因生产线程被抢占而断音。实现后按实际效果调整。

## 与 UTAU 的实测对照

所用装置是两个手动工具。`tests/manual/utauprobe` 写出探针工程，其中每个音符只改变一项属性；在 UTAU 中渲染一次后，UTAU 写出的 `temp.bat` 即为标准答案。`tests/manual/utaucompare` 将 HelloUtau 传给引擎的参数与 UTAU 传递的参数逐项比较。下表每一项都以 455 音符探针的 438 次调用为依据。

| 项目 | UTAU 实测结果 | 结论 |
|---|---|---|
| flags 顺序 | 音符 `g5` + 全局 `B0` → `g5B0`，音符在前 | 笔记正确，stdutau 已修正 |
| flags 中的 `e`/`E` | `e5` → `/e5`，使用正斜杠 | stdutau 正确，笔记误写为反斜杠 |
| Intensity / Modulation / Velocity 缺省值 | 均为 100 | stdutau 正确 |
| 包络第 8 位 | 一律被 oto 的 overlap 覆盖 | stdutau 正确 |
| 包络 10 值写法中的 `%` | 作为一个参数原样传给 wavtool | 此前未知 |
| realLength | `int((duration + fix + stp + 50 + 25) / 50) * 50`，不提升至 consonant | 两处实现均不正确，已修正 |
| 音高曲线的 tick | 不取整，保留小数 | stdutau 曾取整，已修正 |
| 音高值取整 | 四舍五入，而非截断 | stdutau 曾截断，已修正 |
| 音高值个数 | 比 `tick < duration` 多一个 | stdutau 曾少一个，已修正 |
| 颤音最短长度 | **50 毫秒不绘制，51 毫秒绘制**，只省略颤音，音高线照常绘制 | 此前未知，已修正 |
| 过短的颤音 | 不在本音符中绘制，但**延续到下一个音符的音头时仍然绘制，且不带淡入淡出** | 此前未知，已修正 |
| 曲线末尾 | 循环停止于 `duration + 4` 个 **tick**（而非毫秒） | stdutau 曾少一个，已修正 |
| Velocity 超过 200 | **整体退回默认值 100**，而非截断到 200 | HelloUtau 原样使用，**未修改** |
| 颤音淡入淡出 | 重叠时为 `if / else if`，而非相乘 | stdutau 曾相乘，已修正 |
| 缓存名 | `[序号]_[歌词]_[音阶]_[6位].wav`，六位后缀确实存在，**但只取决于时值** | 笔记正确；stdutau 使用长度，HelloUtau 改用摘要，见下文 |

## 缓存

**UTAU 的缓存键不安全，因此未予沿用。** 在 455 音符探针中，其六位后缀只取决于音符的时值：358 个音符带有 163 种不同的 flags，六位后缀完全相同；修改音高线、颤音、包络、Intensity 或 Modulation，六位后缀均不变。而 UTAU helper 中的 `@if exist %temp% goto A` 按文件名判断，文件名不变即跳过重采样。因此修改 flags 后重新渲染，播放的仍是上一次的声音。

HelloUtau 的缓存名前半部分沿用 UTAU（`[序号]_[歌词]_[音阶]_`，供人阅读），最后一段改为**摘要**：对重采样器接收的全部参数，以及样本文件当前的大小和修改时间，一并计算哈希，取六位。

**wavtool 接收的参数有意不计入摘要。** 包络和 StartPoint 在拼接时使用，而非在渲染时使用，因此仅包络不同的两个音符共用同一片段，这是正确的行为。

每次渲染开始前，会删除**同一音符遗留的旧片段**（按文件名开头的序号识别），否则目录会积累每次编辑产生的文件。音符在轨道中移动位置后，旧片段会以旧序号保留。UTAU 存在同样的问题，不值得为此单独维护一个索引文件：该目录属于工程，清空它的代价只是重新渲染一次。

实测结果（作者亲自调校的一首歌曲，96 个发声音符）：

| | 重采样 | 复用 | 耗时 |
|---|---|---|---|
| 空缓存 | 96 | 0 | 3.8 秒 |
| 再次渲染 | 0 | 96 | 1.6 秒，**输出逐字节相同** |
| 修改一个音符的 Intensity | 1 | 95 | 缓存目录中仍为 96 个文件 |

`SynthRunner::reuseCache` 默认启用。禁用它将重新渲染全部音符，适用于引擎本身已更换或其输出存疑的情况。

## 与 UTAU 的偏差

判据有两条，**而非逐采样比较 wav**：同一重采样器处理同一样本，音高相差 1 音分，经过几个周期后采样值就完全不同，但听感完全一致。

1. 参数向量一致：438 次调用中，tone、velocity、flags、offset、realLength、consonant、blank **全部 438/438 一致**。测量值按数值而非文本比较（UTAU 打印时四舍五入，例如 `11.539` 与 `11.5389`），工具会单独报告仅文本形式不同的调用数量。
2. 曲线形状（音分）：见下表。

**探针有意构造极端情况，真实调校工程才是应当关注的一列。** `cuowei` 是作者亲自调校的一首歌曲，含 96 个发声音符：

| | 真实工程 | argument 探针 | vibrato 探针 |
|---|---|---|---|
| 值的数量 | 8673 | 24421 | 13865 |
| 中位数 | 0 | 0 | 0 |
| 均值 | **0.44** | 0.039 | 0.53 |
| 98% 分位 | 3 音分 | 1 音分 | 5 音分 |
| **单个值的最大偏差** | **15 音分** | 13 | 92 |
| 逐点完全相同的音符 | 17 | 365 | 26 |
| 偏差在 5 音分以内的音符 | 91 / 96 | 434 / 438 | 109 / 130 |

真实工程上最大偏差为 15 音分，中位数为 0。颤音探针剩余的 92 音分来自其有意构造的情况（240 bpm 下长 2880 tick 的音符），不会出现在真实调校中。

比较装置在首次运行时发现了两处此前已记录但尚未处理的差异：

- **包络中的 `%`。** 对于 `Envelope=0,5,35,0,100,100,0,10,%,20,30` 这种十值写法，UTAU 将 `%` 作为一个参数原样传给 wavtool，HelloUtau 传递的是 `0`；对于 `0,5,35,0,100,100,0,%,20,30`，HelloUtau 还在末尾多传一个 `0`。涉及 5 个音符。
- **`0Q120`。** 有三个音符在 UTAU 的 `params` 中只有三项（`100 100 0Q120`），没有 `!tempo`，也没有音高字符串；HelloUtau 写出的是 `!120` 加音高字符串。这三个音符分别为 Velocity=200、PreUtterance=0、Tempo=60，其共同点尚未确定。

### 颤音规则的测定

`utauprobe vibrato` 中每个音符两侧均为休止符，因此每个音符的曲线仅属于其自身。

**最短长度以毫秒计**，而非以 tick 或周期计。决定性的证据是三种速度下的同一个音符：同样 96 tick 的颤音，在 60 bpm（200 毫秒）下绘制，在 120 bpm（100 毫秒）下绘制，在 240 bpm（50 毫秒）下**不绘制**。周期也已排除：50 毫秒内含 2.5 个完整周期仍不绘制。

**分界为 50 / 51 毫秒。** 两组相互独立的扫描（24% 的短音符和 12% 的长音符，均安排为每步恰好一毫秒）在同一毫秒处发生变化。

**只省略颤音。** 一个同时带有音高线和过短颤音的音符，其输出曲线与只带音高线时**逐点相同**。

**但该颤音会延续到下一个音符，且不带淡入淡出。** 隔离验证：带颤音的音符自身的两个值全为零，其后跟随一个既无颤音也无音高线的普通音符，该音符的音头却出现满幅的正弦值。长度足够的颤音延续过去时**带有淡化**，因此这并非「相邻音符从不淡化」。这种不对称尚无解释，已测量两次。

**淡入淡出为 `if / else if`。** 淡入 80% 与淡出 80% 会重叠，UTAU 始终优先淡入：包络上升至全程的五分之四时仍为 1.006，下一个值骤降至 0.245，这正是淡出从其原本位置接续的结果。若二者相乘，中段会被压平至 0.39，相差六十音分。不重叠时（20/20、50/50）两种写法结果相同。

### 曲线末尾的零值处理

UTAU 删除曲线末尾的零值。**这不会丢失信息**：曲线结束之后即不弯曲，与零值等价。UTAU 自身也依赖这一点：真实工程 96 个音符中有一半的曲线提前结束，其中一个停在 -500 而音符仍在发声，若引擎保持最后一个值，该音符会低五个半音持续到结束，整首歌将无法正常播放。

HelloUtau 保留这些零值，因为删除它们只能为一条用后即弃的命令行节省几十字节，而一条完整表达的曲线比一条提前结束、依赖约定补全的曲线更易读。

循环停止于 `duration + 4` 个 tick。由于 UTAU 删除末尾零值，其输出曲线的长度只能说明循环**至少**执行到该位置；真正确定终点的是「UTAU 未输出、而 HelloUtau 输出非零」的值，这种情况下 UTAU 的循环确实在该处停止。真实工程将其限定在 3.91 至 4.12 tick 之间。**这个 4 的来源尚未查明**，即音符末尾多出的一个值。

### 未解释的差异

- **`0Q<tempo>`。** UTAU 偶尔在 `params` 中只写三项：没有 `!tempo`，也没有曲线，只有 `0Q` 与速度连写。两个触发条件均已精确确定，各为 6/6：音高线整体位于曲线起点之前；或 pbstart **小于 5 个 tick**（恰好为一个值的间隔，边界位于 5 毫秒与 6 毫秒之间）。两个条件互不相关，看似是两条退化路径共用的同一兜底处理。**HelloUtau 输出格式正常的 `!tempo` 加一条平直曲线，不复刻这种畸形输出。**
- **`Velocity` 超过 200 时退回默认值。** `Velocity=250` 时 UTAU 传递的是 `vel=100`，而非 200。目前只有这一个数据点，下界以及 200 至 250 之间的行为均未测量，因此**未实现**：为越界输入设计钳制规则，若规则有误，比不实现更糟。下一个探针应测定这一点。
- **音符交界处相差半个 tick。** 音符尾部被下一个音符的音高线拉弯的部分，HelloUtau 比 UTAU 早 **0.5 个 tick / 0.27 毫秒**（在 15 对音符上测得，PBS 从 -10 扫描至 -160）。在曲线陡峭处偏差达 13 音分。该偏差以毫秒计比以 tick 计更稳定，但来源尚未查明。

## 验收标准

第二阶段的验收标准见 [`Roadmap.md`](Roadmap.md)：命令行能将 `.ust` 渲染为 wav（**已达成**，见 `tests/manual/ustrender/`），以及与 UTAU 渲染同一工程并进行比较（**已达成**，见上文「与 UTAU 的偏差」）。

比较装置必须可重复执行：同一工程、同一音源、同一套引擎，两侧各渲染一次。它是整个项目中对「与 UTAU 一致」最严格的检验，上表的每一项结论都由它判定。使用方法：用 `utauprobe arguments probe.ust --voice ... --charset GBK` 写出工程，在 UTAU 中渲染，**渲染完成后不要关闭 UTAU**，将 `%TEMP%\utauN` 中的 `temp.bat` 和 `temp_helper.bat` 复制出来，因为 UTAU 退出时会清空该目录，渲染出的 wav 则不需要。然后执行 `utaucompare probe.ust --voice ... --script .../temp.bat`。
